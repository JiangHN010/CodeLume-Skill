# 源码学习教科书写作契约

把本文件用作路由器。一次只写一个章节，并且只读取这个章节需要的写作契约。
只有渐进加载各项契约，而不是一次性全部读取，拆分文件才有帮助。

## 单一目的

交付物用于教学生理解项目怎样设计和实现。面向读者的内容可以包括问题、架构
主线、运行机制、设计推导、复杂模块、与设计相关的失败语义、边界和源码指引。

故障排查手册、面试准备、练习、贡献说明、源码阅读顺序、制作记录、证据快照和
验证报告都不能进入本教科书。只有在失败行为能够解释设计选择或不变量时，才把它
写入正文。

## 渐进加载章节契约

1. 先读取 [project-overview-template.md](project-overview-template.md)，写问题、架构
   主线、职责边界和一条具体运行流程。
2. 每写一项精选设计原则，都读取
   [design-principle-template.md](design-principle-template.md)。写完这项原则后，再读取
   下一个章节契约。
3. 只有模块的内部复杂度能够实质性帮助理解架构时，才读取
   [complex-module-template.md](complex-module-template.md)。简单模块在总览或精简模块
   地图中简要说明。
4. 关系、生命周期、转换或抽象机制可能借助图像表达得更清楚时，才读取
   [visual-learning-assets.md](visual-learning-assets.md)。

## 证据与代码契约

- 源码直接支撑的事实正常陈述，并链接文件和符号。直接事实不加状态标签。
- 只有非事实使用且必须使用这三个标签：`[INFERRED]`、`[UNKNOWN]`、
  `[SUGGESTED]`。标签放在它所限定的句子或段落开头。
- 每段教学改写都使用文档语言标注：中文使用 **伪代码（教学改写，并非源码原文）：**，英文使用
  **Pseudocode (teaching rewrite; not source):**。更换语言、重命名标识符、简化分支
  或重建对象都属于伪代码。
- 逐字代码块只有在与当前检出版本核对后才能标注：中文使用 **源码节选：**，英文使用
  **Source excerpt:**。修改措辞、标识符、注释、顺序或控制流后，必须改为伪代码。
- 专业术语第一次出现时在上下文中解释。先建立不依赖实现语言的直觉，再讲具体
  语法或语言类比。
- 源码链接用于支撑教学，不用于生成面向读者的审计轨迹。重要未知项写进相关讨论
  或精简的边界章节。

## 最小文章结构

只保留范围和证据支撑的章节：

```markdown
# <项目或模块>：<架构主线>

## 代码背后的问题
## 中心设计与一条具体运行流程
## 深入理解设计原则
## 复杂模块：<名称>                    # 仅在确有必要时加入
## 边界与待确认问题                    # 仅保留重要边界
## 源码指引
```

## 最终编辑门槛

把教科书作为一部连贯的教学作品重新阅读。只有同时满足以下条件才算完成：

- 删除包名后，架构主线仍然成立；
- 每项精选原则都满足因果契约，而不是罗列组件或收益；
- 至少沿一个真实输入、事件或状态，讲清具体表示、决策、所有权变化和可观察结果；
- 简单模块没有被强行扩写，也没有装饰性图表；
- 状态标签和代码分类符合证据契约；
- 从保存后的教科书出发，每个相对链接都能解析。
