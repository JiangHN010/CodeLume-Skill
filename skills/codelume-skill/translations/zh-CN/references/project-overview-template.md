# 项目总览章节契约

用本契约写开篇架构叙事和一条纵向运行流程。使用学生所用语言和连贯正文。

## 开篇

从已经验证的问题和使问题变难的压力开始。先用普通语言说明项目的核心架构回应，
再引入框架、模式、包名或语言特性。

通过四个问题解释主要边界：这项职责为什么存在，它拥有什么状态或不变量，把什么
工作委托出去，以及相邻部分怎样观察它的结果。包名是解释的证据，不能代替解释。

## 具体运行流程

选择一个有代表性的输入、事件或状态变化，沿重要边界追踪它。每次转换都要说明：

1. 转换前的具体表示；
2. 触发下一步的决策或不变量；
3. 转换后的表示或被拥有的状态；
4. 负责该步骤的源码符号；
5. 可观察结果或与设计有关的失败语义。

只有语法本身有教学价值时才使用简短、准确的源码节选。使用简化表示教学时，明确
标注为伪代码。

## 完成条件

当读者能够解释架构主线，并能沿不断变化的表示和所有者重放一个真实行为时，本节
才算完成。只有组件列表或缺少因果转换的调用图并不完整。
