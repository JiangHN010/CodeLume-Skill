# 视觉学习资源

当保存的源码学习教科书包含可能借助视觉表达得更清楚的关系、状态、顺序、转换或抽象机制
时，读取本参考。图像用于回答学习问题，不用于证明模块覆盖率。

## 根据复杂度决定

当正文会遮蔽下面任一种结构时，使用确定性的 Mermaid 或仓库原生 SVG：

- 仓库中多个重要职责和边界；
- 顺序、重试、并发或完成时机很重要的流程；
- 状态或生命周期转换；
- 数据所有权或多阶段转换；
- 复杂模块中的内部决策树或算法。

简单包装器、注册表、清单、值类型或线性适配器使用正文说明。模块不会因为进入范围
就自动获得图表。整仓教科书可以使用一张整体架构图；局部模块图取决于机制复杂度，
不取决于模块数量。

为每张入选图保留简短的内部视觉记录：学习问题、已验证的源码依据、视觉形式、放置
位置和资源路径。不能在教科书中暴露记录、选择过程、提示词或废弃资源。

## 选择视觉形式

| 学习需要 | 首选形式 |
| --- | --- |
| 精确架构、依赖、调用链、状态或数据所有权 | Mermaid 或仓库原生 SVG |
| 概念心智模型或隐喻 | 生成式位图 |
| 项目已有且持续维护的视觉资源 | 复用或编辑原生资源 |
| 定量比较 | 使用已验证数据生成图表 |

每个技术节点和箭头都要映射到经过检查的符号、配置、Schema，或者明确标记的推断。
如果图像只是在重复周围正文，就删除它。

## 生成概念插图

只有当插图能够实质性讲清精确方框和箭头难以表达的抽象职责、协调模型、生命周期、
分布式边界、并发模型、检索流程或记忆模型时才生成。项目已有视觉资源或确定性图表
已经讲清思想时跳过。

确定生成时：

**必要子 Skill：** 使用 `imagegen`。

提示词必须建立在已经验证的证据上：学习目标、放置位置、主体、构图、风格、配色和
必须避免的无证据元素。优先不在图中嵌入技术文字；准确名称和标签留在 Markdown 中。

## 保存并验证生成资源

1. 检查虚构组件、错误关系、乱码、Logo、水印和不一致的视觉语言。
2. 把选中图片复制到 `<guide-directory>/assets/<guide-slug>/`，使用稳定且有描述力的文件名。
3. 使用相对路径、有意义的替代文本和下面的证据边界：

   ```markdown
   ![机制的概念视图](assets/<guide-slug>/<image>.png)

   > 概念插图。精确关系由带源码链接的图表或正文定义。
   ```

4. 重新打开 Markdown 和图片，验证渲染以及与周围讲解的一致性。

## 视觉质量门槛

- 每张图回答一个正文无法同样清楚回答的明确学习问题。
- 技术关系具有源码依据；生成图片不包含无证据的架构结论。
- 简单模块只使用正文。
- 相关视觉资源保持统一风格。
- 相对路径能够解析，位图资源保存在教科书旁边。
