# CodeLume-Skill

## 概述

把源码视为设计决策的记录。保存的交付物是一部聚焦项目问题、架构、机制和权衡的源码学习教科书。

**核心原则：** 每个架构职责和运行时跳转都必须能够追溯到源码、配置、测试或命令结果，并且明确保留不确定性。

## 适用方式

选择最小且有用的模式：解释一个符号、追踪一条流程、学习一个模块、梳理整个仓库，或者更新已有源码学习教科书。范围较小时直接回答；用户要求文档或范围跨越多个文件时保存 Markdown。

## 工作流程

1. **明确任务基础。** 确认仓库根目录、设计问题、范围和交付物；读取仓库说明并保留已有修改。除非用户要求缩小范围，否则面向不同经验程度和编程语言背景的程序员写作。
2. **先建立地图，再追踪流程。** 检查构建清单、文档、配置、入口、测试和模块边界。在调用者和真实职责得到确认前，名称只能作为线索。遇到陌生仓库或跨模块流程时，阅读 [references/analysis-playbook.md](references/analysis-playbook.md)。
3. **还原设计。** 找出职责、不变量、边界、实现选择、状态所有权、故障隔离和约束。追踪一条纵向流程，证明这些选择的运行效果。
4. **按因果关系教学。** 写每项重要原则前，先在内部填满八个槽位：设计压力、看似可行的简单方案、具体失败、推导路径、源码机制、收益、代价和边界。证据无法填满全部槽位时，删除或暂缓这项原则。宁可少讲几项，也不要堆积宽泛总结。
5. **按章节写作。** 保存教科书时，把 [references/learning-document-template.md](references/learning-document-template.md) 当作路由器，只读取当前章节需要的写作契约。关系、状态或转换可能需要图示时，再读取 [references/visual-learning-assets.md](references/visual-learning-assets.md)。交付前验证源码链接和代码分类。

## 教科书完成标准

只有同时满足以下条件，教科书才算完成：

- 正文始终围绕当前项目的设计与实现，不混入制作过程或无关任务。
- 读者无需预先熟悉项目或它使用的编程语言，也能理解项目解决的问题、整体架构、主要职责边界和一条完整运行流程。
- 每项重点设计都讲清设计压力、简单方案的局限、项目的推导过程、真实源码机制、收益、代价和适用边界。
- 关键运行流程能够沿真实输入、调用、状态变化和可观察结果在源码中完整追踪。
- 专业术语在第一次出现时得到解释；复杂关系只在确实有助于理解时通过示例或图像说明。
- 源码事实直接链接且不加标签；只有推断、未知和建议需要显式标记。
- 教学改写代码明确标为伪代码；源码节选与当前检出版本保持一致。
- 所有源码链接、相对路径和图像资源都能正确解析。
